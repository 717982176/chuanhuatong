# 使用与维护

## 会话和回复

管理员回复某条访客消息的副本时，收件人由该副本的映射决定。没有有效映射的明确回复不会回退发送给另一个当前联系人。点击联系人气泡或切换会话按钮后，普通消息发送给当前联系人；默认闲置 30 分钟自动退出。

`/send ID 内容` 可以定向发送，成功后计入最近沟通记录。Bot 必须能访问目标聊天：Telegram 不允许机器人随意主动私聊从未与其互动的用户。切换会话只展示近 30 天沟通过、已授权且未封禁的联系人。

## 管理指令

| 指令 | 用途 |
| --- | --- |
| `/start`、`/admin`、`/help` | 欢迎消息、控制台、帮助 |
| `/send ID 内容` | 定向发送文字 |
| `/list` | 最近访客文字列表，10 人一页 |
| `/search 关键词` | 按昵称、用户名、ID、备注搜索；花体昵称可用普通字母 |
| `/search` | 打开搜索输入；搜索成功后清理输入词消息 |
| `/note ID 备注` | 保存备注，最多 80 个 Unicode 字符 |
| `/note ID -` | 删除备注 |
| 回复访客消息发送 `/note 备注` | 给回复对象加备注 |
| `/note 备注` | 给当前会话联系人加备注 |
| `/session 30` | 闲置退出时间，支持 1–1440 分钟 |
| `/session off` | 关闭闲置退出，底层会话仍最多保留 7 天 |
| `/inbox` | 查看待回复；可清理单个联系人、本页或全部 |
| `/done ID` | 手动将对应联系人标记为已处理 |
| `/quick` | 给回复对象或当前联系人打开快捷回复 |
| `/quick list` | 管理快捷回复模板 |
| `/quick add 标题 \| 内容` | 添加模板；最多 10 条，标题 20 字、正文 1000 字 |
| `/quick del 编号` | 删除模板 |
| `/quick 编号` | 发送指定模板 |
| `/away on`、`/away off` | 切换离开模式 |
| `/away text 内容` | 设置离开提示；同一访客 24 小时内仅提示一次 |
| `/diagnose` | 查看请求耗时、接口耗时、Webhook、镜像和失败任务 |
| `/backup` | 创建备份并下载 JSON |
| `/restore` | 开始导入 JSON 备份，预览后再确认 |
| `/cancel` | 取消输入或备份导入 |
| `拉黑 ID`、`解封 ID` | 管理黑名单，封禁默认 30 天 |
| `撤销 ID`、`撤销授权 ID` | 撤销访客授权 |

管理员可以在回复访客消息时直接发送“拉黑”“解封”或“撤销授权”。这些管理操作不会作为聊天内容转达。搜索和备注仅用于管理端，不改变真实昵称或主页链接。

## 交互规则

- 欢迎消息、控制台和同类入口仅维护最新一条，旧消息清理受 Telegram 删除接口的时限和网络影响。
- 翻页、离开模式等按钮操作优先更新原菜单；管理输入互斥，发送 `/admin` 或取消操作后旧确认失效。
- 快捷回复按钮一次有效。使用后清除按钮，并在聊天中保留发送内容或结果记录；旧菜单不会因切换会话而发给错误联系人。
- 待回复只在新留言到达时建立。发送成功或手动完成会清理此前的待回复；编辑、查看列表和切换联系人不会重新制造待回复。
- 自动清理可关闭，或选择 3 / 5 / 7 天；按每条留言的原始时间判断，不因修改或刷新页面延长。
- 列表以文字呈现昵称、数字 ID 和时间，无额外复制 ID 按钮。昵称是否能跳转仍受 Telegram 隐私规则和客户端支持影响。

## 备份与恢复

使用 `/backup` 下载 JSON。备份包含访客资料、授权、备注和管理设置，应私下保存，不能提交到公开仓库。最多保存 10 份内部快照；文件限制 1 MiB、5000 条记录。

`/restore` 后发送备份文件，查看预览再确认。恢复仅接受相同管理员 ID 的有效备份，检查格式、范围、大小和校验和。恢复前自动创建快照；授权、备注和设置按备份范围替换，额外记录会被清理，过期记录跳过，剩余期限不延长。

恢复会使当前会话、输入和旧快捷菜单失效；不会恢复 Bot Token，也不清除消息回复映射。JSON 校验和用于发现内容损坏，不是数字签名；只恢复自己信任的备份。备份不是整个 Durable Object 的完整灾难恢复镜像。

## 诊断与异常

| 现象 | 核查与处理 |
| --- | --- |
| 机器人无回应 | 查看 `webhook-info`，确认生产 Secrets、实际地址与密钥匹配，随后查看 Worker 日志 |
| `Config error` | 必填变量或 `BOT_KV` 缺失；核对生产设置，不只检查本地 `.dev.vars` |
| 缺少 `BOT_STATE` | 核对真实部署配置的绑定和 Durable Object 声明 |
| 验证失败或无法关闭 | 检查 Turnstile 域名和站点密钥，在 Telegram 中重新 `/start`；必要时点击返回聊天 |
| 验证通过后仍未授权 | 确认网页与 Webhook 指向同一部署、同一管理员实例，检查生产绑定 |
| 刚部署短暂无响应 | 看待投递数量和日志，不能仅凭等待时间判断是否部署成功 |
| 修改没有同步 | Webhook 必须订阅 `edited_message`；映射仅对仍在保留期内的消息有效 |
| 原生“已编辑”未显示 | 检查副本正文或图片是否更新；客户端标记不能由 Bot 参数强制开启 |
| 原生转发下没有访客按钮 | 原生转发可能不能修改键盘；系统使用引用身份卡，保留原作者和原有按钮 |
| Telegram 429 | 尊重限流；相册和可重试编辑按延迟调度，避免反复点击制造更多请求 |
| 发送显示“待确认” | 网络结果不明，先核对接收方记录，避免盲目重发造成重复消息 |
| KV 镜像持续积压 | 检查绑定、额度和持续失败键；实时状态仍由 Durable Object 管理 |
| KV `Value out of range ... 2147483647` | 升级到 1.0.1，旧到期值在同步时规范化并通过相对 TTL 写入；不需要清空 KV 或 Durable Object。持续失败仍应查看最新诊断 |
| KV 每日用量预警 / 429 | 50% 预警不等于额度已耗尽；在 Cloudflare 账号查看读、写、删除、列出的分别用量，也核对其他 Worker 和手动操作 |
| 旧按钮失效 | 刷新控制台获取当前菜单，不重复使用已取消或到期的确认 |

```powershell
npm.cmd run webhook-info
npx.cmd wrangler tail --config wrangler.jsonc
```

日志和诊断会对配置密钥做脱敏，分享之前仍应检查是否含用户消息、昵称、ID 或备份内容。常规维护包括升级前备份、发布后验收、检查持续错误和镜像积压，以及及时处理凭据泄露。

### KV 到期与额度

KV 到期字段使用 Unix 秒，联系人资料等 `updatedAt` 字段仍使用毫秒。1.0.1 兼容到期字段中大于等于 `10^12` 的历史毫秒整数，其他正整数按秒处理；不是任意损坏数据的自动恢复器。无法解释的字段保留任务并记录错误，不通过删除任务伪装同步成功。

镜像保留 Durable Object 中的绝对期限，写入 KV 时计算剩余秒数，避免原生参数的有符号 32 位上限。剩余不足 60 秒时删除旧镜像，不为满足 KV 最小 TTL 而延长授权或数据寿命。失败后各任务按 2、4、8 秒逐步延迟，最多 15 分钟；实例重建不丢失延迟。

免费套餐的每日限制分别为读取 100,000 次，写入、删除、列出各 1,000 次，按账号累计，每日 UTC 00:00（北京时间 08:00）重置。达到某类限制后，该类操作可能继续失败至重置；参数越界与额度耗尽属于不同问题，升级套餐不修复非法参数。官方说明：[KV 额度和计费](https://developers.cloudflare.com/kv/platform/pricing/)、[写入到期参数](https://developers.cloudflare.com/kv/api/write-key-value-pairs/)。

升级后查看 `/diagnose` 的待同步数量和最新失败时间。旧失败记录会继续保留在历史列表，不代表仍在发生；不要清空生产存储或重复设置 Webhook 来消除历史记录。
