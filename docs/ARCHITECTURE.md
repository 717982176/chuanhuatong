# 架构与边界

## 请求处理

Worker 的 GET `/verify` 返回验证页面；POST `/verify-submit` 接收 Telegram Mini App `initData` 与 Turnstile 结果。其余 POST 作为 Telegram Webhook 处理，入口先检查 Webhook Secret。

网页提交和 Webhook 均路由到按 `bot:<管理员ID>` 命名的同一个 `BotCoordinator`。协调器使用 Durable Object 持久化状态和串行任务队列，避免不同请求读取跨地区 KV 的旧授权。授权写入后才向网页返回成功；欢迎消息和通知在后台执行。

Mini App 的用户 ID 来自服务器验证过的签名数据。服务端检查 HMAC、签名时间和用户 ID；未授权访客还需要通过 Turnstile。客户端自己提供的用户 ID 不能替代这套验证。实现遵循 [Telegram 身份校验文档](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app)。

## 状态与兼容

`CoordinatedStore` 提供兼容 KV 的读写接口。既有 KV 数据按需导入，后续即时读写以 Durable Object 持久化记录为准；变化合并后在后台同步到 `BOT_KV`。镜像失败会延后重试，并轮换批次，避免一个失败键长期阻塞其他数据。

因此，KV 是兼容层和延迟镜像，不能直接编辑 KV 代替机器人管理操作，也不能把 KV 镜像当成当前状态的强一致快照。Worker、管理员 ID、协调器类名或命名空间变化，都需要独立的数据迁移方案。

## 消息传递

消息副本保存原消息到转达副本的映射，便于原位编辑；管理员收到的副本另外保存访客映射，供直接回复。普通内容尽量复制，真正转发的内容优先保留原生转发来源和可保留的按钮；无法修改原生转发键盘时，使用引用身份卡。

连续访客消息的身份气泡保留在该组最新消息处。管理员真实回复、其他访客和未知分隔保留边界。受管理的指令或菜单确认删除后，历史记录移除对应分隔，并合并相邻同一访客的分组；原内容、原键盘和回复映射不因此删除。

分组历史最多保留 256 条事件，详细指针保留 30 天。没有记录的旧历史、管理员手动在 Telegram 客户端删除的消息，以及已超出历史窗口的分隔，不能可靠地自动推断合并。

相册先等待约 0.9 秒收集，单批最多等待 3 秒，以 `copyMessages` 保留分组。队列任务、发送检查点和编辑重试存放于 Durable Object，实例重建后继续处理。很晚到达的成员可能作为补充批次发送。

## 保留期与限制

| 数据或策略 | 当前规则 |
| --- | --- |
| Webhook 成功更新去重 | 24 小时 |
| 原消息 / 副本映射 | 30 天 |
| 最近联系人 | 近 30 天沟通记录 |
| 黑名单 | 默认 30 天 |
| 当前会话 | 默认 30 分钟闲置退出，底层保存 7 天 |
| 管理员回复保护 | 180 天，互动刷新 |
| Mini App 签名 | 最长 1 小时，允许有限时钟偏差 |
| 访客消息限流 | 3 秒内最多 3 条，相册按一批计算 |
| 管理搜索上下文 | 15 分钟 |
| 管理输入与确认 | 通常 10 分钟 |
| 列表分页 | 每页 10 人 |
| 待回复自动清理 | 可关闭，或选择 3 / 5 / 7 天 |
| 内部备份 | 最多 10 份；每份 1 MiB、5000 条记录 |

联系人资料与最近记录分离保存，避免沟通记录到期导致所有显示名称丢失。这里不提供“删除所有用户数据”的合规管理工具；部署者应根据实际用途制定自己的数据保留和删除方式。

## 平台边界

- Telegram Bot API 没有本项目可用的外发幂等键。确认发送成功后会尽量恢复记录而不重发；网络响应丢失时先标记待确认，无法保证所有故障下都恰好发送一次。
- 机器人删除消息、编辑消息、保留转发来源、访问无用户名用户主页，都受 Telegram 能力、隐私设置和客户端影响。
- 对可编辑的副本调用原生编辑接口；不可编辑的原生转发可能需要单独更正消息。Telegram 右下角编辑标记、验证窗口关闭及移动端排版不能由本项目完全控制。
- 原生按钮中的第三方回调仍归原 Bot 处理，本项目不能替原 Bot 执行业务逻辑。
- 一个 Bot 的状态集中在一个协调器实例。串行队列提高一致性，慢外部请求也可能占用队列；不宣称无限吞吐或多租户隔离。
- `/backup` 是受控业务快照，保留期限和范围有明确限制，不是所有即时任务、镜像与消息历史的完整导出。

Cloudflare 的配额与 Durable Object 可用性以账号实际方案为准。声明式 SQLite 配置见 [Wrangler 文档](https://developers.cloudflare.com/workers/wrangler/configuration/)。
